# CRRT calculator audit, v1.7.0 (2026-09-23)

All results below come from running the code: a Node harness for the engine, and jsdom driving the real Prescribe page (clicking Generate, typing into fields, reading the rendered outputs and warnings).

## Findings and fixes

| # | Finding | Severity | Fix |
|---|---|---|---|
| 1 | Typed values were stored as strings, so editing any flow turned addition into concatenation. Editing Qd to 1600 displayed a delivered dose of 1,383,272,647 mL/kg/hr. Present in every prior version. | Safety-critical (absurd rather than subtle, but it made every manual edit unusable) | Inputs are stored as numbers; every engine call goes through one coercing helper. Test U1. |
| 2 | The live code had lost many earlier changes (v1.5.x text edits, live update, Step 2 citrate selector, heparinized option, Regiocit default). Each session had started from stale files. | Clinically significant (process) | Consolidated the full repo; upload the whole zip. |
| 3 | The UI re-split replacement and recalculated dialysate after the engine, so predictions and warnings described a different prescription. | Clinically significant | The split is now an engine input (preFilterShare: 20% citrate, 50% otherwise). The UI uses engine flows unchanged. Test U2, 0 mismatches in 8,640 UI runs. |
| 4 | False "target not reached" at normal weights, caused by rounding down to 50 mL/hr. | Clinically significant | Dialysate top-up after rounding. Test R4. |
| 5 | Invalid haematocrit (below 0), uptime of 0 and negative net UF produced flows without a warning. | Clinically significant | Input guard. Test R6. |
| 6 | Overshoot from net UF or rounding (not only citrate) was not warned. | Clinically significant | Generalised dose-floor check plus a catch-all. Test R7. |
| 7 | Replacement orders of 50 mL/hr and CVVHDF with zero dialysate and no explanation. | Cosmetic, plausibility | Tiny flows are folded or moved to dialysate; a notice appears when citrate alone provides the dose. Test R5. |
| 8 | The schematic showed a dash for Qb after any edit because it tested a string with Number.isFinite. | Cosmetic | Coerced in schematic.js. |
| 9 | The FF ceiling was hard-coded. | Design | Configurable in config/local-protocol.json (ceiling, ceilingWithPreFilterCitrate, redThreshold), default 25% / 25% / 30%. Test R1, R2. |

## Sweeps (patched build)

- UI path matrix, 8,640 runs (5 anticoagulation/product settings × 4 modalities × weight 40–150 × Qb 100–250 × Hct 0.20–0.45 × net UF 0–500 × uptime 0.7/1.0): no NaN or Infinity, no negative flows, no FF above the ceiling without a warning, 0 unflagged dose misses (1,492 flagged, almost all pure CVVH at the FF ceiling), 0 unflagged overshoots (267 flagged, all dilute citrate in small patients).
- Engine random sweep, 20,000 cases with 15% degenerate inputs: 0 invariant violations.
- UI random sweep, 1,500 cases with degenerate typed values: no NaN, Infinity or undefined rendered.
- tests/tests.html: 57 passed, 0 failed (16 new regression checks, including 5 that drive the real UI).

## Verified correct

Citrate flow matches 10 × Qb exactly for 18 mmol/L at 3 mmol/L, round trip exact at 7 blood flows. ACD-A at 3.0 mmol/L gives 1.59 × Qb; Tolwani's 1.5 × Qb corresponds to 2.8 mmol/L. Calcium conversions (CaCl2 0.68, gluconate 0.22 mmol/mL), accumulation ratio above 2.5, three-way acid-base discrimination, phosphate removal, sodium gradient, Devine IBW and adjusted weight: all correct. Heparin dosing is not computed in the UI.
